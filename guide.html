Browser Edition: First Test

Open Block Coding, Simulator and Dashboard in separate tabs in the same browser profile, signed into the same account and server address. Their existing page layouts are unchanged. Block programs execute locally; login and saved designs remain on the server.

Demo 1: Temperature Monitor

In Simulator, add a temperature sensor and seven-segment display. In Block Coding, click Load and choose Demo 1 - Temperature Monitor, then Run. Move the temperature slider: the display, gauge and graph follow it. Open Dashboard to view the cards.

Other Demos

Demo 2 - Temperature Traffic Light: add temperature sensor, seven-segment and CJP. Below 20 C is blue, 20 through 30 C is green, above 30 C is red. Demo 3 - Parking Assistant: add ultrasonic and CJP; below 20 cm is red, otherwise green. Demo 4 - Joystick Status: CJP directions light the corresponding LED and update an info card. CJP is already on the stage.

Run, Stop and Save

Run and Stop control a browser worker, not a server Python process. Stop retains dashboard values. Closing the running Blockly page stops the program. Save and Load need an Internet/server connection; after the pages and worker have loaded, live simulation and dashboard updates work without one. Local state belongs to this account in this browser profile. Clearing site data removes it.

Scope

AI, physical USB/Web Serial and advanced gadget/sprite blocks are postponed. Unsupported blocks show an error instead of silently executing on the server. The Python IDE remains server-side and is outside this browser-runtime test; its database dashboard is separate from local browser cards.

Deployment

Use a separate Ubuntu test host. The installer will not convert an existing platform-server installation. Use HTTPS for a public server. This is a trusted-user prototype, not a hostile-code sandbox. Background-tab throttling can affect timing.
